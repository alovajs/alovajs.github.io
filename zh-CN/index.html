请求场景模型（RSM）

请求场景的四个生命周期

以这四个生命周期阶段为指引，每一类请求场景都能被完整地组织起来，它们清楚何时触发、何时复用、何时真正发出请求，而不再依赖零散的人工拼装。

请求场景概念arrow_forward
阶段 01play_circle

请求触发

在合适的时机触发请求，例如手动触发、状态变化、翻页、网络重连等，减少不必要的请求。

触发01 / 触发
阶段 02schema

请求决策

判断发出请求前应如何处理本次请求。

评估02 / 决策
阶段 03swap_horiz

请求执行

网络通信发生，通常由 fetch、axios 或 XHR 等处理。

委托03 / 执行
阶段 04auto_awesome

数据应用

获得响应数据后的动作，如界面更新、自动转换、缓存更新和多端同步，以及后续步骤的使用等。

整合04 / 应用
RSM 信封原则

把触发、决策、执行与数据应用封装进同一个内聚的场景

alova 干净地位于你的传输层之上。axios 与 fetch 负责网络，alova 接管生命周期的其余部分。

RSM 核心→axios / fetch→零样板
默认即拥有

一个请求策略，不止于发起请求

alova 的请求策略默认提供超出预期的完整请求功能，无需在提示词里额外说明。

      localStorage.setItem('refresh_token', refresh_token)
    }
  }
