## S1 · Hero（01 Scenario）

**主张与文案**

- 主标题：`The unit of a request isn't a call — it's a scenario.`
- 副文案：`A request has a lifecycle, yet your code scatters it across components — and AI just copies it.`
- 按钮 1：`Getting Started` → `/tutorial/getting-started/introduce`
- 按钮 2：`GitHub` → `https://github.com/alovajs/alova`
- 安装命令（可复制）：`npm i alova`

**右栏：双态代码演示（自动播放 + 两个页签）**

页签：`Handwritten` 与 `alova declaration`，共用一个舞台，双态在同一位置叠放切换。

播放规则：

- 进入视口后自动播 **2 轮**，播完停在 `alova declaration` 态；
- 用 `setTimeout` 链驱动，不用 `setInterval`；离开视口 ≥ 500ms 停表、重置为 alova 态、轮次归零；
- 点击任一页签即永久停止自动播放；hover/点击「重播」可再看 2 轮；
- `prefers-reduced-motion: reduce` 或 < lg 断点下完全不自动播放。

页签 1：`Handwritten`——同一「搜索分页」场景被切碎在 4 张色卡上。**颜色即阶段**，卡面只放语义伪代码、不放文件名/提示行头部（除 Execution 用 `fetch(...)` 具象指代请求工具外，不出现框架/库级 API 名），阶段名称与出现位置由底部图例承担：

Trigger 卡（`var(--stage-trigger)`）

```txt
keyword, page  ← user input / paging
when they change:
  emit(keyword, page)
```

Decision 卡（`var(--stage-decision)`）

```txt
if cached(key):     return cached(key)
if inFlight(key):   return inFlight(key)
if stale(response): drop(response)     // by hand
```

Execution 卡（`var(--stage-execution)`，全篇最短，收拢时最后移动且不虚化）

```txt
fetch('/api/search', { keyword, page })
// the only part your request tool owns
```

Data application 卡（`var(--stage-apply)`）

```txt
rows ← normalize(response)
setState(rows)
notify(rows); persist(rows)
```

底部图例（颜色 → 阶段 → 出现位置）：

- Trigger — `SearchInput.tsx`
- Decision — `useSearch.js`
- Execution — `fetch()`
- Data application — `ResultList.tsx`

页签 2：`alova declaration`——同一场景收拢为一次 `usePagination` 调用：

```ts
const searchList = keyword => (page, pageSize) =>
  alova.Get('/api/search', { params: { keyword, page, pageSize } });

const { data, loading, page, pageCount, total, onNextPage } =
  usePagination(searchList(keyword), {
    watchingStates: [keyword],
    debounce: 300,
    cacheFor: 60 * 1000,
    preloadNextPage: true
  });
```

下方能力标签 5 个：`Pagination`、`Debounce`、`Cache`、`Data preloading`、`Stale-response handling`

**时间轴（单轮约 3.7s，两轮约 7.4s）**

| 阶段 | 时长 | 画面 |
| --- | --- | --- |
| 入场 | 0 | alova 态（SSR 默认输出，结构稳定、无 JS 时也完整） |
| 展开 | 0.7s | 4 张色卡错峰炸开到各自散落位（60ms/张） |
| 驻留 | 1.2s | 手写态静置阅读 |
| 收拢 | 0.8s | 卡片向中心收拢 + 虚化，火花飞入 + 冲击环（复用现有 `sparkFly` / `sparkRing`，仅第 1 轮播） |
| 点亮 | 1.0s | alova 声明出现，按阶段逐行点亮（行内不写注释，映射只靠行色）：Execution（`alova.Get`）→ Trigger（`watchingStates`）→ Decision（`debounce` / `cacheFor`）→ Data application（`preloadNextPage`），每行 160ms |

**实现要点**

- 时间轴拆成独立 hook（`useReplayCycle`），`index.tsx` 只消费 `panel` / `phase` / `replay()`；所有 timeout 集中 `clear`。
- `.stage` 需显式 `min-height`（约 340–380px，需实测），否则绝对定位卡片会让高度塌陷、切换时跳动（当前高度靠手写层撑开）。
- 收拢位移由每张卡的 `--dx / --dy / --rot / --delay` 预设，不做 JS 测距；**transform 从 `.layer` 下移到 `.card`**（现有实现是整层 `scale(0.72)`，无法表现「各自归位」）。
- SSR 默认 `alova`（现有实现默认 `handwritten`，无 JS 时会停在绝对定位的散落画面上）。
- < lg：卡片退化为纵向堆叠、位移归零、不自动播放，保留 `mobileToggle` 手动切换。
- 删除不再使用的 `.fragment*` 与整体揭示动画 `rsm-code-reveal`（其 clip-path 与绝对定位卡片叠加会裁切），手写态改为卡片错峰淡入。
- 颜色不是唯一信息：卡片保留阶段文字（图例）与 `aria-hidden` 分层；非激活层不可聚焦。

## S2 · Request Scene Model（02）

**Intro**

- eyebrow：`02 · Request Scene Model`
- 标题：`alova is a request strategy library.`
- 描述：`It treats the scenario as the basic unit of a request, with reusable strategies organizing the complete journey from trigger to data application.`
- 链接：`Learn the Request Scene Model` → `/about/RSM`

**四个阶段模块**（每个含：序号、阶段名、一问、一述）

| 序号 | 阶段 | 问题 | 说明 |
| --- | --- | --- | --- |
| 01 | Trigger | When is a request needed? | State changes, user actions and timers all create the need for data exchange. |
| 02 | Decision | How should this request be handled? | Decide whether to hit the network at all, and how to deal with cache and request sharing. |
| 03 | Execution（弱化展示） | How to talk to the server? | Send the request through axios, fetch, XHR — and take the response back. 附注：`Just this one segment — handed to your request tool.` |
| 04 | Data application | How does the response enter the business? | Transform data, update state, manage cache and exchange data across components. |

> 内容潜台词：整条链路里只有 Execution 这一段交给请求工具，其余三段由 alova 的策略承担。
